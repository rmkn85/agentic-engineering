# Progressive visual artifacts: overview to detail to usable output

Reviewed: 2026-09-27. Status: measured native invocation and downstream mechanics; controlled generative drilldown and remote binary delivery remain unaccepted. A successful continuation does not establish uniform capability across hosts or future turns.

[Execution kernel](../agent-corpus/README.md) · [Observation economy](observation-economy.md) · [Bounded recovery](bounded-recovery.md) · [Surface selection](surface-and-pool-selection.md)

## Preserve the outcome, not just the picture count

A multi-panel concept contains a hierarchy of related design decisions. Its useful expansion is `overview -> identified region -> new detailed design -> editable semantic source -> working consumer`. An exact crop preserves a reference; resampling enlarges pixels; new generative development invents additional detail; reconstruction authors geometry; implementation supplies behavior. Record these as different operations. A crop, screenshot or directory count is not a count of independent image generations.

The desired graph is not necessarily a tree: one detailed component can serve several assemblies, and one screen can reuse several components. Keep stable IDs, parent/reference hashes, scope and disposition without duplicating every shared asset. A changed parent invalidates affected descendants, not unrelated completed work. A decorative panel does not automatically need its own generated asset.

## Capability admission before an expensive batch

Inspect six seams separately: native generation; reference readback; file retention; visual inspection; deterministic processing; authorized repository delivery. For model delegation, also verify an actual model-worker launcher and each worker's tool access. A product subscription, public announcement, skill file or previous successful session does not prove those seams exist in the current execution surface.

Inspect the native tool surface separately from connector/plugin discovery. A search of one connector's functions says nothing about the presence of a built-in image tool. When the native tool is listed and the request authorizes generation, invoke it on one useful bounded deliverable before writing an availability explanation or switching providers. An earlier assistant assertion is not a capability snapshot. Distinguish no invocation, a currently omitted tool, an actual invocation error, an inaccessible returned file and a returned image that fails the requested design. These require different remedies.

A text write action is not a local binary-file bridge. An action accepting a content string does not accept a path in place of bytes unless its contract explicitly says so. Preserve binary data through supported file references or an authenticated native worker; do not transcribe large base64 payloads through model text. Do not shrink a detailed master into a thumbnail merely to fit an inadequate transport route. A missing bridge is a precise unverified seam, not proof that Git or the account is read-only.

If the required generator is actually missing, report that gate immediately with its observed scope. Bounded independent processing can remain useful, but cannot replace the requested generation experiment or justify calling the whole route complete. A simulation of a queue predicts behavior; it does not measure a provider. Never execute paid alternatives or install/connect accounts merely because the preferred tool is absent.

## A minimal progressive-generation trial

1. Read the authorized source and identify the intended consumer. Name observed invariants and uncertain details separately. Fix the parent revision and source rights.
2. Generate one overview through the actual available image tool. Retain the returned bytes immediately. Record requested versus returned settings/model identity; leave unexposed fields unknown.
3. Read and inspect the generated parent. Identify a coherent region and record native-pixel coordinates. Give a child job both the whole parent for context and the selected crop for identity.
4. Generate one new detailed child at an adequate native resolution. Inspect structural identity, labels, functional landmarks and consistency. Qualify invented hidden surfaces; do not claim they were recovered from the picture.
5. Expand one selected child into an editable specification and working consumer. Validate the actual consumer and the delivered image derivative.
6. Commit the image, provenance and valid preview together through an authorized byte-safe route. Re-read the remote revision, verify hashes/decoding and inspect the served preview. Blob creation, branch integration and displayed output are separate claims.

Only then profile a bounded family. Use fixed independent child briefs and the same reviewed parent; rotate serial and parallel treatment order. Parent-dependent jobs cannot run correctly before their references exist. Prefer one normal candidate per job and at most one justified repair before reassessing the representation or brief. The limit is an example bounded trial, not a universal generation policy.

A new overview returned in response to an isolated-detail request is a failed output contract, even when attractive. Retain the requested instructions, supplied references and actual returned identity. Do not assert effective prompt or reference binding when the host does not expose it. Narrow request isolation is a hypothesis to test; repeatedly appending stronger wording to the same unsuccessful context is not a proven recovery mechanism. Do not count painted wireframes, performance numbers or completion badges as real downstream artifacts.

## Measure each stage and preserve unknowns

Record monotonic request/return/retention intervals, provider job IDs when exposed, dimensions, output bytes, encode/decode time, inspection/retry disposition, upload/readback time and exact input/output identities. Separate provider queue time only when observable. Cost and usage remain unknown unless actually returned; a shared rounded usage meter is not precise job cost.

For throughput, report attempted, returned, retained, technically valid, visually useful and integrated outputs separately. Useful integrated children per elapsed time is more informative than generated files per minute. Report cohort size, repeats, cache state, failures and stopping reason. A successful cohort is a tested size, not a maximum capacity or rate limit.

Distinguish local processes, model workers and independent sandboxes. Prove overlapping model-call intervals before claiming parallel generation. Overlapping compression processes establish only parallel compression. A missing capability produces a not-run result, not a zero-latency success and not an estimate of the model's capacity.

## Storage and transport

Retain the actual original and its provenance. Use a native-resolution lossless derivative when exact pixels matter; verify decoded dimensions and pixel equality. A smaller thumbnail is an additional navigation artifact, not the master. Lossy delivery needs a separate review at the detail that matters. Matching dimensions does not establish matching pixels; matching pixels does not establish matching metadata.

Validate full decoding and container length before admission. Use bounded atomic writes and output identity checks. A timeout can occur after a remote operation completed: inspect the existing job/blob/commit before retrying. Resume the failed stage, never regenerate unchanged art to fix a link or transfer error. Keep branch updates non-forced and reconcile current remote state.

An inline-data preview is useful as a portable offline bundle; it is not the most efficient normal web layout. Separate cached image files and optional thumbnails usually avoid base64 overhead and repeated payloads. Test the actual permitted viewer. An in-memory browser test does not establish HTTP, file-navigation, GitHub-preview or production-serving acceptance. Do not bypass a blocked route to manufacture that claim.

## Two acceptance tracks

**Mechanism:** can the file be retained, decoded, transformed, versioned, selected and manipulated without losing its declared identity/state? Use accepting and rejecting controls.

**Meaning and craft:** does the detailed child preserve useful design relationships, and does the implementation remain recognizable and serve its intended task? A colored primitive, attractive screenshot or passing schema cannot answer this alone. For interfaces, preserve editable text, states and interaction structure. For geometry, preserve semantic parts, pivots, connections and declared behavior. Images are references, not authoritative hidden topology or physics.

A coarse functional proxy can pass mechanism acceptance while failing visual fidelity. Keep both dispositions explicit. Likewise, a beautiful image can pass visual direction review while failing the functional contract.

## Bounded observations that motivated this procedure

An anonymized local derivative trial processed six fixed image regions three times each with one, two and four operating-system processes. Median wall times were 0.598543, 0.352794 and 0.234117 seconds (about 1.70x and 2.56x over serial). This includes process startup and decode verification; it is not a hosted-generation benchmark, a model-worker experiment or a universal recommendation to use four workers. Source media and detailed receipts remain private.

A source-preserving WebP derivative reduced a roughly 3 MB PNG by 35.04% without resizing or changing decoded pixels. This is one image, not a codec-wide saving estimate. A temporary local bare-Git push/clone/readback preserved roughly 3 MB original image bytes and a roughly 5 MB preview. That proves local Git mechanics, not remote service authentication or upload limits.

A rendered prototype initially passed command/state checks while its terrain was invisible. Inspection found a winding/culling defect; a deliberate hidden-ground control subsequently qualified a narrow rendered-presence check. Another viewport passed interaction checks while clipping its principal object. These failures show why command correctness and no-overflow checks do not establish composition or visual fidelity. They do not justify a universal image-quality score.

The initial trial did not run hosted generation or model-subagent throughput. The follow-up below updates native invocation evidence without retroactively changing that initial result.

### Native invocation follow-up — 2026-09-27

One assistant continuation returned four successive native image attachments and readable PNG files without a new manual image invocation or alternate paid API. All were 1672 x 941. Paired monotonic observations for the first two gave 70.750 and 61.553 seconds from request preparation to observed return, including orchestration overhead. The other two timings were not measured. This is a bounded serial cohort in one context, not four independent sessions, a rate-limit test or parallel workers.

Returned originals were 2544342, 2493469, 2455841 and 2195664 bytes. Their lossless WebP derivatives were 2083704, 2038152, 2015106 and 1743662 bytes, with decoded RGBA equality. Exact provider model identity, effective rewritten prompt, quota and monetary cost were not exposed. No such field was inferred from a metadata heading or product announcement.

A generated parent was read back and a 128 x 132 reference crop displayed for the next step. Follow-up output remained a broad poster rather than the requested isolated full-resolution part. Thus four retained native outputs established callability, while zero outputs passed the controlled-child contract. Private subjects, artwork, generation identifiers and project paths are deliberately not published here.

The native Git route failed at name resolution before authentication. The connector's text-write capability was independent and did not establish a byte-safe local-file bridge. These results do not diagnose historical tool exposure or account permissions. Cross-session consistency, controlled detail, model parallelism and remote binary delivery remain open.

### Documented behavior versus this observation

OpenAI's [Images in ChatGPT](https://help.openai.com/en/articles/11084440-images-in-chatgpt) help page, checked 2026-09-27, describes generation from a conversation request or the Images selector, and editing a generated/uploaded reference. This supports the intended product route, not an assertion that every planner context exposes identical tools or guarantees reference fidelity. No official source retrieved in this check explained the user's specific manual-versus-assistant routing discrepancy. The successful native calls above are direct evidence; inferred causes of earlier no-call reports remain hypotheses.

## Do not generalize yet

Do not create a universal art platform, a private-asset mirror, a new task registry or a model-specific scheduler for this workflow. Reuse the existing asset owner, native encoders, Git client and consumer tests. Keep provider capability snapshots dated and conditional. Replace unknown measurements only with actual execution receipts; neither a checklist nor repeated successful invocation alone establishes a complete production chain.
