# Efficient execution

1. **Preserve the outcome.** Keep the requested scope, acceptance, evidence, permissions, and quality. For broad transformations, map the requested scope to owned deliverables; structural success is not substantive acceptance.

2. **Select the cheapest adequate model AND effort.** Optimize expected total cost through acceptance, including transfer, verification and likely rework. Use exact tools for exact work and keep tiny tasks local. The [dated routing policy](../../docs/local-codex/subagents.md#named-model-and-effort-policy) supplies concrete defaults without an installed allowlist: `gpt-6.1-sol`/`medium` for substantial coding/orchestration; `gpt-6-luna`/`medium` for focused workers, lowered to `low` for routine extraction, small edits and established-rubric checks. Allowed worker pairs are Luna at `low|medium|high` and Sol at `medium|high`. The coordinator may explicitly choose Sol and/or High for a specific capability or reasoning need, with a short task-based reason; no failed cheap attempt is required when the gap is already clear. Do not inherit the parent's cost settings. Never dispatch `gpt-6-astra`, an unapproved replacement model, or `xhigh|max|ultra` workers. Astra planning is user-directed, not an automatic worker escalation. Route down after resolving ambiguity. Roughly 80/20 Luna/Sol and mostly Medium-or-lower effort are workload expectations, never quotas or spending caps.

3. **Keep context lean.** Retain verbose logs, tool output and captures with the executor; expose status and decisive excerpts or artifact paths first. If a large MCP catalogue repeatedly dominates input, compare direct tools with [progressive schema disclosure](../../docs/local-codex/tooling.md#tool-schema-disclosure), including schema lookups, cache effects, latency and accepted results. Load procedures and evidence only for the current decision. At phase boundaries, update existing task notes with outcomes, decisions, owned changes, evidence paths, blockers and the next action so runtime compaction can preserve continuity. Notes do not themselves remove earlier context.

4. **Reuse valid work, not expensive configuration.** Treat completed semantic work and deterministic artifacts as cached until an input that can affect them changes. Do not reread, regenerate, or revalidate merely to demonstrate activity. Reuse a worker only after its known model, effort, context and remaining budget pass the same dispatch contract; otherwise transfer the useful result to a compliant worker without restarting completed work.

5. **Validate proportionally.** Run targeted checks after local changes and broader acceptance at integration/final boundaries. Before scaling a repeated assignment, inspect one representative result against the user's actual outcome.

6. **Make dispatch explicit and bounded.** Before each launch, fork, resume or follow-up, deliberately select an allowed supported model/effort pair and bounded context using actual controls or an inspected role. Define outcome, owned scope, constraints, authoritative inputs, finite numeric assignment/aggregate budgets and acceptance. Follow-ups and repairs debit the same allocations; workers do not redelegate or reset budgets. Reject omitted/inherited cost selection, unsupported controls and out-of-policy resolved settings. Use the [launch preflight](../../docs/local-codex/subagents.md#launch-preflight). For native Codex V2, verify override exposure and select `fork_turns` explicitly; current full-history forks can override models, while follow-up messages cannot reconfigure a worker. Preserve intentional V2 mode hints separately from worker defaults; use the [source audit](../../docs/local-codex/multi-agent-v2.md) when configuration is the decision. Require a compact return covering result, revision/scope, changed files, checks, evidence, failures, uncertainty, remaining acceptance and available usage. Inspect decision-critical evidence; do not replay routine worker work. Record requested/resolved settings from native evidence when available. Distinguish soft assignment budgets from native whole-tree exhaustion controls and possible accounting overshoot. Verify supported choices once per run and reuse the mapping until relevant evidence changes; no separate policy installation or repeated model research is required.

7. **Treat instructions as a costed resource.** If this skill conflicts with persistent guidance or repeatedly fails under realistic context, fix placement/decision boundaries or enforcement instead of adding unlimited prose. General advice to preserve defaults, reuse context or select stronger specialists never overrides the explicit worker policy. If no allowed worker is adequate or selectable, keep necessary work with exact tools/the authorized coordinator within applicable native budgets and preserve unresolved acceptance; do not buy an Astra worker or weaken the goal.

8. **Measure only when the decision is uncertain.** For repeatable material tradeoffs, capture `codex exec --json` (or equivalent) usage plus substantive acceptance. Compare total task cost including workers, coordination, retries and repairs. Model/effort mix and worker usage share are diagnostic signals, not efficiency verdicts. API prices are not a conversion for subscription credits. Do not claim savings from worker counts, prompt length, or one anecdote.

For task-to-tier examples, budget/reuse controls and native limitations, read [`docs/local-codex/subagents.md`](../../docs/local-codex/subagents.md). For instruction/context placement and adherence tests, read [`docs/local-codex/prompts-skills-agents.md`](../../docs/local-codex/prompts-skills-agents.md) and [`experiments/instruction-context-adherence.md`](../../experiments/instruction-context-adherence.md) only when that decision is relevant.
