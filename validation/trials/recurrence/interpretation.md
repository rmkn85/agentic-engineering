## Native execution and lifecycle proof

Writable private state and the complete pinned CLI 0.167.0 package enabled native
execution. The previous conclusion that a normal terminal or privileged access
was required was incorrect. [CODEX_HOME](https://learn.chatgpt.com/docs/config-file/environment-variables)
provides the private state route. Original host configuration stayed unchanged;
the private copy retained permissions, rules and instructions, adding only scoped
neutral-project trust and reviewed hook hashes. Credentials are not published.

The existing outer sandbox enforced containment. The explicitly selected native
CLI inner `danger-full-access` mode omitted redundant wrapping inside that
controlled environment; [noninteractive guidance](https://learn.chatgpt.com/docs/non-interactive-mode)
scopes this mode to isolation, while the [app-server protocol](https://learn.chatgpt.com/docs/app-server)
provides `externalSandbox` for an already sandboxed host. The runner freezes and
rechecks expected outer restrictions. No filesystem/socket permission, approval
rule or trust control was bypassed. This cooperative environment check is not
hostile-host attestation; default execution still uses the native sandbox.

A separate, explicitly assisted [final-source lifecycle probe](host-integration/final-source-receipt.json)
retained host `hook/started` and `hook/completed` events: Start delivered audit
context; Stop blocked three times, then ended with explicit incomplete status;
after operator repair and executed verification, the next Stop completed with
accepted evidence. This proves the pinned adapter/host path and bounded retry
behavior. It is not an autonomous recurrence run or retroactive proof of every
hook invocation in the scored exec transcripts.
