# First matched pair: independent validity review

Scope: only p01 baseline and candidate, their frozen source corpus, native receipts, authority and external recurrence evaluator. No held-out assets, model launches or source changes. Reproductions use separate disposable copies. Original scored receipts are unchanged.

## Acceptance derived from authority before implementation review

The original request requires executable correction and recurrence prevention, binding claimed success to current acceptance and relevant inputs, preserving failed attempts, and normal native matched sessions. It expressly permits both arms succeeding to be inconclusive; comparative superiority is not a merge condition.

The fixture task requires a working order-summary export with JSON total and row count, preserved total behavior, empty/nonempty consumer evidence, and an ordinary workflow that meets REQUEST. The seeded optional consumer target cannot justify completion while export is unfinished. The native ordinary and finish routes must reject an incomplete export and accept the accepted final product. There is no authority to replace shared methodology history with a project checkpoint. Iterator support is not an explicit acceptance requirement, but is compatible additional coverage: total already handles iterables, and the implementation adds no behavior conflicting with the request.

## Separate verdicts

1. Product/workflow outcome: candidate actual product meets the tested independent consumer outcome and ordinary-route behavior. Baseline original receipt passes all existing assertions. There is no demonstrated candidate product regression in this pair.
2. Genuine candidate integrity problem: the worker overwrote `.agentic-engineering/docs/dev-handoff/README.md` and deleted project `HANDOFF.md`. This erased shared corpus continuation content and relocated project records inside the dependency snapshot. Its original integrity=false and passed=false must remain. This is not cured by independent consumer success.
3. Fixture/adoption ownership ambiguity: root AGENTS explicitly says shared-corpus paths resolve inside the embedded tree while only source, goal and requirements resolve to the project. Handoff ownership is omitted. More seriously, native work_audit enumerates all tracked paths, ranks a README before shorter handoff paths, and explicitly directs rewriting the embedded handoff and deleting HANDOFF.md. The worker log records following this directive. The same handoff selection logic exists in both frozen source arms; the candidate audit diff changes goal freshness, not this heuristic. Thus the worker's edit is real, but treating this as clean evidence that candidate reflection independently caused unauthorized dependency mutation is unsupported.
4. Oracle defect: the positive control replaces the accepted worker implementation with a narrower canned implementation. Candidate's valid iterator test then fails because canned REPAIRED calls len(iterator). The ordinary routes are correctly rejecting a product regression introduced by the evaluator. Both positive-control assertions are false failures for the intended workflow property. Do not fix this by deleting or weakening the iterator test.
5. Pair-level result: preserve the original failed/invalid candidate and successful baseline records; do not rescore them into a comparative win, remove failed attempts, or infer superiority. A corrected rerun is a new trial revision with retained provenance, not a repair of the old record. Truthful-completion and native-hook invocation remain unknown where the original receipts report unknown; this review does not infer them from exit codes.

## Smallest legitimate corrections

For evaluator positives, use the independently accepted actual final product unchanged. Run independent consumer acceptance first, then its actual ordinary and finish routes; apply the retained broken mutation in a separate copy to prove rejection. This checks acceptance of the worker's valid result and failure discrimination without dictating implementation shape. Keep external independent consumers and broken controls intact. If a canonical restoration control is retained, it must satisfy all legitimate existing worker tests; changing REPAIRED to materialize iterables repairs this particular defect but remains vulnerable to other compatible implementation choices. Version and freeze the corrected oracle before new sessions; retain current receipts.

For ownership, fix the reusable adoption boundary as well as the neutral fixture. A dependency corpus is not the consumer project's handoff. The generic entry template/adoption guidance should declare project-owned handoff/task paths and shared dependency paths. The native audit should accept or derive an explicit owner-declared project scope and exclude declared shared/vendor corpus from project rewrite recommendations. Test this with a project HANDOFF plus an embedded corpus README: neither prose nor an audit recommendation may authorize overwriting the dependency. Preserve the ability to audit that dependency explicitly when methodology maintenance is the authorized task.

A fixture-only handoff exception would reduce ambiguity in this experiment but leave the measured generic audit defect intact for real adopters. Avoid hardcoding this project's directory in generic policy or silently suppressing all handoff checks. Conversely, do not modify broad always-loaded instructions merely to coach the worker through this scenario. The smallest sufficient fixture amendment is neutral ownership mapping aligned with the generic contract, applied identically to both new arms. Source changes require their own new frozen candidate identity and reviews.
