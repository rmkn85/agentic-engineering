# Efficient execution

0. **Start from the focus.** Run `python3 <agentic-engineering>/tools/work_audit.py --root <repository>` and do its FOCUS line in this session. A request for "the next task" includes it: close any records task that blocks it in one short commit, then continue. Only a request that names a different task overrides it. When your work writes to an area the audit flags (task list, handoff, instructions), leave that area within its limits in the same commit. Moving duplicated instructions into one source changes no rule and needs no owner decision; changing what a rule says does. Check a finding before acting on it; if it is wrong, add `{"kind", "path", "reason"}` to `ignore` in `.agent/audit.json` in the same commit so no later agent is sent there. The audit reads the repository's history: records-only loops, repeated steps, unfinished code, handoff bloat. Progress is changed behaviour that a check proves.

1. **Preserve the outcome.** Keep scope, explicit user priorities, permissions, source coverage and acceptance. Select from the actual remaining outcome gap; a ready task or proposed solution is not its own priority or proof of necessity. For integrated work follow [direct delivery](../../docs/execution/direct-delivery.md): complete the next missing connection for a common user journey through the existing owner and prove the usable result. Its qualitative 80/20 and nested 70/30 guides tie enabling work to the journey and keep process support compact, without quotas or acceptance exemptions. Reconcile corrections with active worker briefs; missing checks remain open, never silently deferred acceptance.

2. **Choose the executor and count for the next outcome.** Decide whether tools, the current coordinator, an existing compliant worker or a new worker should do it, then choose how many concurrent agents are useful, including zero. Context isolation, specialized attention, continuity and independent parallel progress must justify their coordination cost. A saved app model selection is not this decision; changing a default does not replace it. Keep tightly coupled judgment local. Use deterministic tools for mechanical work; a worker may supervise a long/noisy operation when compact reporting frees the coordinator for useful work. Run a stable documented command without reading its implementation unless a failure or contract question requires it.

3. **Route the next phase, not the whole project.** Select the task's model and effort from the canonical [named policy](../../docs/local-codex/subagents.md#named-model-and-effort-policy), including its scoped Terra visual/writing route. Choose effort for remaining uncertainty, not project size; High needs a specific reasoning bottleneck. Execute settled plans, reopening decisions only on material new evidence; use alternatives for a real open decision. Diagnose failures before changing effort and route down after resolving uncertainty. Use the defaults unless a representative sample can plausibly repay its full overhead across substantial remaining work. See the [decision and sampling rules](../../docs/local-codex/subagents.md#choose-effort-for-the-unresolved-decision). Do not force ratios or a failed cheap attempt. **Never use Ultra unless the current owner instruction explicitly says to exhaust allowance before reset.** That exception stops at the first observed exhaustion, reset or owner deadline; paid credits do not extend it. Use tools/Luna for monitoring even then. Preserve the stop contract across workers and resumes.

4. **Choose lifetime and preserve useful work.** Distinguish [portfolio orchestrators, autonomous epic owners, persistent steering reviewers, bounded specialists and short execution workers](../../docs/local-codex/subagents.md#worker-lifetime-and-integration). A short worker returns its bounded result; an epic owner retains context and its worktree, chooses next steps, resolves blockers and delegates authorized work through actual accepted delivery, potentially for hours or days. Checkpoints and token/time estimates are observations, not invented stop budgets or renewal gates. Track cumulative use and genuine limits; keep diagnostic attempts bounded without ending the epic. A low-traffic reviewer retains direction and prior corrections, waking for useful checkpoints rather than polling continuously. Reuse compliant model, effort, context and authority; transfer specialist results to Luna/Sol for routine execution and never reactivate expired Ultra. If configuration must change, use a supported compact handoff. Reuse valid findings/caches and the scoped [documentation preflight](../../docs/local-codex/context-caching.md#native-documentation-result-preflight); [clear owned scratch](../../docs/local-codex/context-caching.md#cache-lifecycle-and-cleanup) only after durable evidence is preserved. Use Sol 6.1's [larger context](../../docs/local-codex/context-caching.md#use-a-larger-model-window-deliberately) for coupled work, not unrelated logs.

5. **Make dispatch explicit and proportional.** Select model, effort and context through supported controls; describe role/lifetime, outcome, ownership, authority, acceptance, next checkpoint and any real limits with their source. Carry the actual prerequisites and applicable actor, client and capability access into child context; do not imply access or authority the child lacks. Do not manufacture a numeric epic budget when none was authorized. Give independent concurrent writers persistent [owned worktrees/branches](../../docs/collaboration/git-write-safety.md#parallel-worktrees-and-pr-coordination); coordinate shared boundaries and integration, not each ordinary next step. Use coherent PRs where repository policy requires them. Follow-ups/replacements and authorized descendants preserve cumulative observations and genuine limits. Prefer sandboxed work; bind truly external activities to [reviewed parameterized Make commands](../../docs/adoption/native-command-bindings.md#sandbox-first-external-activities) with narrow activity approval/allowlisting, never ad-hoc inline escalation. Only authorized epic orchestrators/co-developers may delegate; descendants retain that scoped authority. See [launch preflight](../../docs/local-codex/subagents.md#launch-preflight) when needed.

6. **Keep evidence compact and steer the next action.** Keep verbose logs/captures with the executor; return result, changed artifacts, decisive evidence and unresolved acceptance. The parent inspects decision-critical evidence before integrating or claiming the result. Validate one representative result before multiplying a pattern. At meaningful checkpoints use [steering-delivery](../steering-delivery/SKILL.md) and the [outcome scorecard](../../docs/measurement/metrics.md#outcome-and-complete-operation-scorecard). Routine failures stay with the tool or owning worker for bounded recovery; bring only an unresolved decision to the coordinator. Stop unchanged structural or permission retries. Send the concrete failure and next acceptance check to the owner; use independent review when fresh judgment can change the decision. Run efficient unit and integration checks on the delivery path, with QA/product review where required for approval; do not invent exhaustive qualification gates. Coalesce bookkeeping with meaningful task updates or commits.

7. **Keep the process smaller than the work.** Load guidance once for the relevant decision; refresh when authority or inputs change. Verify available launch controls once per run, not before every follow-up. Names record requested scope, reason, lifetime, autonomy, context, model and effort where the owner's convention requires it; they do not prove runtime settings. Preserve existing task notes for continuity; do not add a parallel tracker. When configuration itself is in question, consult the [V2 audit](../../docs/local-codex/multi-agent-v2.md), distinguishing historical source findings from live controls.

8. **Check usage against the work from time to time.** At meaningful checkpoints use the [native Codex usage API](../../docs/local-codex/subagents.md#usage-reasonableness-checkpoints), collected with tools/Luna, to compare depletion with rough expected work/pace, progress and reset horizon. No fixed percentage, cadence or burn goal applies. Investigate unexpectedly fast depletion: model/effort, context, retries, duplication and fan-out, plus shared-account activity or possible platform/reporting faults. A single/coarse snapshot cannot attribute a cause. Remove waste, slow or stop when warranted; seek owner approval before materially accelerating spending beyond current explicit authorization. Reset proximity alone grants no acceleration or Ultra.
