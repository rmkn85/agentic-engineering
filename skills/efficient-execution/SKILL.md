# Efficient execution

1. **Preserve the outcome.** Keep scope, permissions, source coverage and acceptance. For integrated work follow [direct delivery](../../docs/execution/direct-delivery.md): one current user outcome, existing owner path, coherent implementation and real acceptance. Reconcile corrections with active worker briefs; missing checks remain open, never silently deferred acceptance.

2. **Choose the executor and count for the next outcome.** Decide whether tools, the current coordinator, an existing compliant worker or a new worker should do it, then choose how many concurrent agents are useful, including zero. Context isolation, specialized attention, continuity and independent parallel progress must justify their coordination cost. A saved app model selection is not this decision; changing a default does not replace it. Keep tightly coupled judgment local. Use deterministic tools for mechanical work; a worker may supervise a long/noisy operation when compact reporting frees the coordinator for useful work. Run a stable documented command without reading its implementation unless a failure or contract question requires it.

3. **Route the next phase, not the whole project.** Use the [named policy](../../docs/local-codex/subagents.md#named-model-and-effort-policy): deterministic tools first; Luna/Low for usage monitoring, Git operations and CI-log triage; Luna/Medium for bounded coding; Sol 6.1/Medium for sustained reasoning and engineering; Astra/Medium or High for extremely creative or complex graphics, architecture or academic reasoning. High needs a specific reasoning need. Do not force ratios or a failed cheap attempt. **Never use Ultra unless the current owner instruction explicitly says to exhaust allowance before reset.** That exception stops at the first observed exhaustion, reset or owner deadline; paid credits do not extend it. Use tools/Luna for monitoring even then. Preserve the stop contract across workers and resumes.

4. **Choose lifetime and preserve useful work.** A [short-lived worker](../../docs/local-codex/subagents.md#worker-lifetime-and-integration) returns one bounded accepted result and stops; a long-lived domain owner retains shared invariants and feedback across coherent iterations, with cumulative limits and an integration/retirement boundary. Reuse only when model, effort, context and remaining allocation fit the next phase. Transfer specialist results to Luna/Sol for operations/engineering; never reactivate expired Ultra. If follow-up controls cannot change configuration, use a compact handoff to a compliant replacement. Reuse valid findings and caches, then [clear owned scratch](../../docs/local-codex/context-caching.md#cache-lifecycle-and-cleanup) after durable evidence is preserved. The coordinator inspects decisive evidence rather than repeating investigation. Use Sol 6.1's [larger context](../../docs/local-codex/context-caching.md#use-a-larger-model-window-deliberately) for coupled work, not unrelated history/logs.

5. **Make dispatch explicit and proportional.** Select model, effort and context through supported controls; describe outcome, ownership, authority, acceptance, allocation and stops. Give independent concurrent writers [owned worktrees/branches](../../docs/collaboration/git-write-safety.md#parallel-worktrees-and-pr-coordination); coordinate through coherent PRs and one integration owner where repository policy uses PRs. A brief task needs a brief handoff; sustained owners need checkpoints, not a ceremony per message. Follow-ups/replacements and authorized descendants share cumulative limits. Prefer sandboxed work; bind truly external activities to [reviewed parameterized Make commands](../../docs/adoption/native-command-bindings.md#sandbox-first-external-activities) with narrow activity approval/allowlisting, never ad-hoc inline escalation. Only explicitly authorized co-developers may delegate. See [launch preflight](../../docs/local-codex/subagents.md#launch-preflight) when needed.

6. **Keep evidence compact and steer the next action.** Keep verbose logs/captures with the executor; return result, changed artifacts, decisive evidence and unresolved acceptance. Validate one representative result before multiplying a pattern. At meaningful checkpoints use [steering-delivery](../steering-delivery/SKILL.md): the coordinator compares progress and investment, executes justified in-scope corrections, and verifies their effect instead of waiting for a user nudge. Keep decision rationale and follow-up in tasks or commit messages, not source/configuration. Send the concrete failure and next acceptance check to the context-owning agent; use independent review when fresh judgment can change the decision. Repeated failure should change the hypothesis or mechanism, not merely produce another similar variant. Run focused checks during edits and required broader checks at integration.

7. **Keep the process smaller than the work.** Load guidance once for the relevant decision; refresh when authority or inputs change. Verify available launch controls once per run, not before every follow-up. Names record requested scope, reason, lifetime, autonomy, context, model and effort where the owner's convention requires it; they do not prove runtime settings. Preserve existing task notes for continuity; do not add a parallel tracker. When configuration itself is in question, consult the [V2 audit](../../docs/local-codex/multi-agent-v2.md), distinguishing historical source findings from live controls.

8. **Check usage against the work from time to time.** At meaningful checkpoints use the [native Codex usage API](../../docs/local-codex/subagents.md#usage-reasonableness-checkpoints), collected with tools/Luna, to compare depletion with rough expected work/pace, progress and reset horizon. No fixed percentage, cadence or burn goal applies. Investigate unexpectedly fast depletion: model/effort, context, retries, duplication and fan-out, plus shared-account activity or possible platform/reporting faults. A single/coarse snapshot cannot attribute a cause. Remove waste, slow or stop when warranted; seek owner approval before materially accelerating spending beyond current explicit authorization. Reset proximity alone grants no acceleration or Ultra. Keep counts, tokens, credits and accepted-task cost distinct; missing telemetry stays unknown. Do not launch nested clients or bypass permissions to manufacture proof.
