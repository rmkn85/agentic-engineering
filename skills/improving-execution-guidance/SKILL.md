# Improve how the same work is executed

Identify the observed failure and existing owner. Separate the requested product outcome from avoidable execution work. Preserve scope, permissions, resource limits and acceptance. A local workaround is not automatically a universal rule.

Choose the cheapest reliable intervention: remove unnecessary work; fix an existing script/config/test; improve scoped routing; or add a bounded on-demand procedure. Do not default to more root instructions, another agent, a new task store or a custom context compiler.

Define applicability by process capability, not incident history. Include the motivating case, a contrasting case that should not trigger the intervention, possible regressions and rollback. Exercise actual behavior where available. File presence, generated-document equality and a worker's success report are not sufficient proof.

Generalize reusable mechanisms with neutral examples. Keep private incidents, project decisions, internal links and identifying environment data with their owner. Preserve substantive rationale separately from the compact operating procedure.

Promote a supported improvement upstream, then selectively adopt reviewed copies in relevant repositories. Record source revision and intentional adaptation; preserve required resources and local policy. Do not auto-update running tasks from upstream or overwrite local changes silently.

Retain, revise or revert according to evidence. Report executed tests, unrun host/model/delivery layers and the same-outcome comparison. Do not claim token savings without observed usage. Remove superseded duplicate instructions only after the replacement's routes and behavior are verified.

Output: mechanism, applicability, versioned change, evidence, rollback and remaining validation. Related deeper material: the existing instruction-adherence experiment and practice-lifecycle guidance, loaded only for a decision that needs them.
