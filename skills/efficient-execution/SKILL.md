# Efficient execution

1. **Preserve the outcome.** Keep scope, permissions, source coverage and acceptance. For integrated work follow [direct delivery](../../docs/execution/direct-delivery.md): one current user outcome, existing owner path, coherent implementation and real acceptance. Reconcile corrections with active worker briefs; missing checks remain open, never silently deferred acceptance.

2. **Choose the executor and count for the next outcome.** Decide whether tools, the current coordinator, an existing compliant worker or a new worker should do it, then choose how many concurrent agents are useful, including zero. Context isolation, specialized attention, continuity and independent parallel progress must justify their coordination cost. A saved app model selection is not this decision; changing a default does not replace it. Keep tightly coupled judgment local. Use deterministic tools for mechanical work; a worker may supervise a long/noisy operation when compact reporting frees the coordinator for useful work. Run a stable documented command without reading its implementation unless a failure or contract question requires it.

3. **Route the next phase, not the whole project.** Select the task's model and effort from the canonical [named policy](../../docs/local-codex/subagents.md#named-model-and-effort-policy), including its scoped Terra visual/writing route. High needs a specific reasoning need. Do not force ratios or a failed cheap attempt. **Never use Ultra unless the current owner instruction explicitly says to exhaust allowance before reset.** That exception stops at the first observed exhaustion, reset or owner deadline; paid credits do not extend it. Use tools/Luna for monitoring even then. Preserve the stop contract across workers and resumes.

4. **Choose lifetime and preserve useful work.** Distinguish [portfolio orchestrators, autonomous epic owners, persistent steering reviewers, bounded specialists and short execution workers](../../docs/local-codex/subagents.md#worker-lifetime-and-integration). A short worker returns its bounded result; an epic owner retains context and its worktree, chooses next steps, resolves blockers and delegates authorized work through actual accepted delivery, potentially for hours or days. Checkpoints and token/time estimates are observations, not invented stop budgets or renewal gates. Track cumulative use and genuine limits; keep diagnostic attempts bounded without ending the epic. A low-traffic reviewer retains direction and prior corrections, waking for useful checkpoints rather than polling continuously. Reuse compliant model, effort, context and authority; transfer specialist results to Luna/Sol for routine execution and never reactivate expired Ultra. If configuration must change, use a supported compact handoff. Reuse valid findings/caches and the scoped [documentation preflight](../../docs/local-codex/context-caching.md#native-documentation-result-preflight); [clear owned scratch](../../docs/local-codex/context-caching.md#cache-lifecycle-and-cleanup) only after durable evidence is preserved. Use Sol 6.1's [larger context](../../docs/local-codex/context-caching.md#use-a-larger-model-window-deliberately) for coupled work, not unrelated logs.

5. **Make dispatch explicit and proportional.** Select model, effort and context through supported controls; describe role/lifetime, outcome, ownership, authority, acceptance, next checkpoint and any real limits with their source. Do not manufacture a numeric epic budget when none was authorized. Give independent concurrent writers persistent [owned worktrees/branches](../../docs/collaboration/git-write-safety.md#parallel-worktrees-and-pr-coordination); coordinate shared boundaries and integration, not each ordinary next step. Use coherent PRs where repository policy requires them. Follow-ups/replacements and authorized descendants preserve cumulative observations and genuine limits. Prefer sandboxed work; bind truly external activities to [reviewed parameterized Make commands](../../docs/adoption/native-command-bindings.md#sandbox-first-external-activities) with narrow activity approval/allowlisting, never ad-hoc inline escalation. Only authorized epic orchestrators/co-developers may delegate; descendants retain that scoped authority. See [launch preflight](../../docs/local-codex/subagents.md#launch-preflight) when needed.

6. **Keep evidence compact and steer the next action.** Keep verbose logs/captures with the executor; return result, changed artifacts, decisive evidence and unresolved acceptance. Validate one representative result before multiplying a pattern. At meaningful checkpoints use [steering-delivery](../steering-delivery/SKILL.md) and the [outcome scorecard](../../docs/measurement/metrics.md#outcome-and-complete-operation-scorecard). Routine failures stay with the tool or owning worker for bounded recovery; bring only an unresolved decision to the coordinator. Stop unchanged structural or permission retries. Send the concrete failure and next acceptance check to the owner; use independent review when fresh judgment can change the decision. Run efficient unit and integration checks on the delivery path, with QA/product review where required for approval; do not invent exhaustive qualification gates. Coalesce bookkeeping with meaningful task updates or commits.

7. **Keep the process smaller than the work.** Load guidance once for the relevant decision; refresh when authority or inputs change. Verify available launch controls once per run, not before every follow-up. Names record requested scope, reason, lifetime, autonomy, context, model and effort where the owner's convention requires it; they do not prove runtime settings. Preserve existing task notes for continuity; do not add a parallel tracker. When configuration itself is in question, consult the [V2 audit](../../docs/local-codex/multi-agent-v2.md), distinguishing historical source findings from live controls.

8. **Check usage against the work from time to time.** At meaningful checkpoints use the [native Codex usage API](../../docs/local-codex/subagents.md#usage-reasonableness-checkpoints), collected with tools/Luna, to compare depletion with rough expected work/pace, progress and reset horizon. No fixed percentage, cadence or burn goal applies. Investigate unexpectedly fast depletion: model/effort, context, retries, duplication and fan-out, plus shared-account activity or possible platform/reporting faults. A single/coarse snapshot cannot attribute a cause. Remove waste, slow or stop when warranted; seek owner approval before materially accelerating spending beyond current explicit authorization. Reset proximity alone grants no acceleration or Ultra. Keep counts, tokens, credits and accepted-task cost distinct; missing telemetry stays unknown. Do not launch nested clients or bypass permissions to manufacture proof.
