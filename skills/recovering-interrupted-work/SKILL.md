# Recover an existing task

Read the repository entry, existing task/claim and smallest current handoff. Preserve its authorized outcome and acceptance. Do not invent a replacement task ledger or restart completed work.

Establish actual repository/ref/HEAD, working-tree state and current remote evidence. Preserve unrelated changes, active ownership and incomplete Git operations. Read back uncertain writes before retrying. Use a native source guard when available. Never force, reset or switch a shared checkout to make history match an old note.

Compare the recorded checkpoint with current source and affected interfaces. Reuse unchanged evidence; invalidate only evidence whose inputs changed. Determine what is implemented, tested, integrated and delivered independently.

Classify the blocker: unavailable tool/transport, denied capability, missing declared dependency, stale source, ownership conflict, failed hypothesis, implementation defect or inadequate acceptance. Prefer the existing safe route. One diagnosis and revisit condition replaces repeated setup attempts; do not alter system privileges or copy credentials.

Continue the smallest useful owned increment. Leave source identity, decisive evidence, unresolved state and one next action in the existing task record at a natural checkpoint. Persist useful work through the authorized Git path and verify the remote result. An unavailable physical device or production resource remains an explicit acceptance boundary.

Output: recovered checkpoint, work retained, checks actually run, exact remaining blocker and next executable action. No private reasoning transcript, hidden background-work promise or invented completion.

Detailed guidance: `docs/collaboration/git-write-safety.md` and `docs/adoption/newcomer-contract.md` in the adopted engineering snapshot or upstream reference. The procedure above is self-contained.
