# Efficient execution

1. **Preserve the outcome.** Keep scope, permissions, source coverage and acceptance. For integrated work follow [direct delivery](../../docs/execution/direct-delivery.md): one current user outcome, existing owner path, coherent implementation and real acceptance. Reconcile corrections with active worker briefs; missing checks remain open, never silently deferred acceptance.

2. **Choose delegation for a concrete benefit.** Context isolation, specialized attention, continuity and independent parallel progress are reasons, not fixed agent categories. Keep tightly coupled judgment local. Use deterministic tools for mechanical work; a worker may supervise a long or noisy operation when compact reporting frees the coordinator for useful work. Run a stable documented command without reading its implementation unless a failure or contract question requires it.

3. **Choose capability, effort, context, lifetime and autonomy independently.** Use the [named routing policy](../../docs/local-codex/subagents.md#named-model-and-effort-policy): Luna low/medium for clear work, Sol medium for substantial reasoning/development, high for a specific need. Apply explicit owner-authorized co-developer exceptions within their scope. Do not force model ratios, require a failed cheap attempt, or treat a large input as proof that a stronger model is needed. Optimize total effort through acceptance, including transfer, coordination, verification and rework.

4. **Preserve useful continuity.** Reuse an agent when its domain context, capability and remaining allocation fit the next work. Send corrections and evidence back to that owner. Start fresh when isolation, stale context, different capability or ownership makes it cheaper overall. A short routine follow-up need not discard an expensive but useful context; compare replacement cost. Cache valid findings and artifacts until relevant inputs change. The coordinator inspects decisive evidence rather than repeating the delegated investigation.

5. **Make dispatch explicit and proportional.** At launch select model, effort and context with supported controls; describe outcome, owned scope, authoritative inputs, constraints, acceptance, allocation and stop conditions. A brief task needs a brief handoff. A sustained domain owner or co-developer needs integration boundaries and checkpoints, not a new launch ceremony per message. Follow-ups carry the existing contract and allocation, stating only changes. Respect owner/native limits; never reset consumed budgets by relabeling work. Only explicitly authorized co-developers may delegate, and descendants share the lane's limits and ownership boundaries. See [launch preflight](../../docs/local-codex/subagents.md#launch-preflight) for details only when needed.

6. **Keep evidence compact and steer the next action.** Keep verbose logs/captures with the executor; return result, changed artifacts, decisive evidence and unresolved acceptance. Validate one representative result before multiplying a pattern. At meaningful checkpoints use [steering-delivery](../steering-delivery/SKILL.md): the coordinator compares progress and investment, executes justified in-scope corrections, and verifies their effect instead of waiting for a user nudge. Keep decision rationale and follow-up in tasks or commit messages, not source/configuration. Send the concrete failure and next acceptance check to the context-owning agent; use independent review when fresh judgment can change the decision. Repeated failure should change the hypothesis or mechanism, not merely produce another similar variant. Run focused checks during edits and required broader checks at integration.

7. **Keep the process smaller than the work.** Load guidance once for the relevant decision; refresh when authority or inputs change. Verify available launch controls once per run, not before every follow-up. Names record requested scope, reason, lifetime, autonomy, context, model and effort where the owner's convention requires it; they do not prove runtime settings. Preserve existing task notes for continuity; do not add a parallel tracker. When configuration itself is in question, consult the [V2 audit](../../docs/local-codex/multi-agent-v2.md), distinguishing historical source findings from live controls.

8. **Measure uncertain tradeoffs honestly.** Use available native telemetry and accepted outcomes when comparison could change routing. Worker counts, model mix and shorter instructions do not establish savings. Distinguish soft allocations from native exhaustion controls and exact spending caps. Missing telemetry stays unknown; do not launch nested clients or bypass permissions to manufacture proof. Fix conflicting instruction placement rather than adding more policy prose.
